一句话讲给评委

原来寿命预测用"烤房盖了多少年"来定退化曲线，导致健康分其实很高、刚保养过的老烤房被一刀切判为寿命归零。升级后我们直接信任系统算出的健康分，用它在退化曲线上反推"这台房现在相当于几岁的新房"，同时维修还有几次真账就延寿几年——于是"修得好 = 健康分高 = 等效年轻 = 寿命更长"这条业务逻辑被完整打通，不再被物理年龄卡死。

第 1 步 信息化数据从哪来（输入层）

系统为每栋烤房建立"一房一档"，健康分与寿命的全部输入来自以下四类信息化记录：

① 烤房档案
kf_basedata：建成年度(finish_date)、乡镇/村、使用状态
② 部件台账
加热/散热/自控/主体四张表：状态、评价、修复年份
③ 管护·人工
manage_mode（集中/分户）、manual_eval（好/中/差）
④ 维修台账
repair_records：已验收/审核通过 + 完工日期(end_date)
⑤ 退化折算
年份差→部件已用年限 Δt→CDCI三段式退化
⑥ 输出回流
健康分0-100 + 剩余寿命(年) + 预警等级 + 退役年份
🔑 每条数据的用途
  • 建成年度 → 计算房龄与部件已使用年限 Δt；
  • 部件状态 + 上次修复年份 → 状态分 S_status 与退化分 S_degrade 的输入；
  • 管护制度 / 人工评价 → 三维融合中的第 2、3 维，体现"管不管"与"现场复核"；
  • 维修台账 → 双重作用：① 健康分侧重置退化年龄；② 寿命侧真实计数延寿（升级 U2）。

第 2 步 健康分三维融合算法（现状值 0-100）

主公式
H健康分 = 0.80 × C部件 + 0.10 × M管护 + 0.10 × A人工 // 满分 100

部件 80 分、管护 10 分、人工 10 分 —— 与《三个模型建模初步建议》"主要部件80 + 现行管护制度10 + 人工评价10"结构完全一致；部件内部采用本项目实际运行的 4 组加权框架（AHP 层次分析确定权重）。

2.1 部件健康分 C部件（权重 80% 的承载主体）

由四组部件加权：加热设备 JR + 散热器 SR + 自控设备 ZK + 烤房主体 ZT，每组内部再由"状态 + 退化 + 评价"三维构成：

C部件 = 0.30·JR + 0.26·SR + 0.26·ZK + 0.18·ZT // 权重来自 AHP（加热最重要、散热与自控次之、主体最低） 某部件 Ci = 0.40·S状态 + 0.30·S退化 + 0.30·S评价
部件组权重对应部件表子项（状态列）
JR 加热设备0.30kf_heater燃烧机 burner_status
SR 散热器0.26kf_radiator管道/燃烧室/灰门/烟囱
ZK 自控设备0.26kf_controller冷风门/电机/排湿窗/循环风机/助燃风机/控制柜/水壶/探头（8项）
ZT 烤房主体0.18kf_oven_body墙体屋顶/挂烟梁/大门（3项）

2.2 三个子分怎么定

子分取值
S状态正常=100 · 异常=50 · 损坏=0
S评价较好=80 · 一般=60 · 较差=50 · 差=30
S退化见右：CDCI 三段式退化函数

2.3 退化分 S退化 —— CDCI 三段式

Δt = 今年 − max(部件修复年份, 维修台账最新完工年份) // 未修过按默认 5 年起算 稳定区 Δt ≤ 0.2L → 100 线性区 0.2L < Δt ≤ 0.7L → 100 − k₁(Δt − 0.2L), k₁ = 100/(0.5L) 加速区 Δt > 0.7L → 30·e^(−k₂(Δt − 0.7L)), k₂ = 2/L

L 为部件设计寿命（JR=10、SR=12、ZK=10、ZT=20 年，界面可调）。越接近寿命终点退化越快，贴合烤房设备真实老化规律。

2.4 管护分 M 与人工分 A（权重 10% + 10%）

维度档位 → 得分说明
管护制度 M集中管护=100 · 分户管护=80集中管护设备更统一、退化更慢
人工评价 A好=100 · 中=80 · 差=50技术员现场复核，吸收照片/表单覆盖不到的经验

管护与人工两维在界面可直接下拉录入（管护制度 / 人工评价），未录入默认"集中管护 + 好"兜底（各给满分），保证每栋烤房都能算出分。

2.5 维修台账联动（健康分回弹）

读取该烤房维修列表中"已验收/审核通过 + 完工日期非空"记录，按维修类型与描述关键词归到四部件组（加热→JR、散热热风→SR、自控电路探头→ZK、保温屋顶大门→ZT，无法归类记入通用组 ALL），以其完工年份作为该部件退化起始年：

退化起始年 = max( 部件表修复年份 , 维修台账最新完工年份 )

效果：修过关键部件的烤房，退化年龄重新从维修当天起算，健康分明显回弹——让维修投入直接体现在健康分上，与寿命侧的真实计数延寿互为印证。

① 读取原始部件数据（表内真实值）
部件L 寿命状态评价修复年份Δt(2026)
JR 加热器10正常较好20224
SR 散热器(4项)12均正常较好20224

② 逐部件算 Ci（三步代入 CDCI）

    C_JR = 0.4·100 + 0.3·60 + 0.3·80 = 82.0
  • SR：Δt=4 ∈ 线性区(2.4,8.4] → k₁=16.67 → S_d=73.3

  • ZT：三子项 S_d=(墙体8→60, 梁2→100, 门17→加速22.2)，平均60.7

第 3 步 剩余寿命预测算法（BDRL 升级版）

寿命预测不再用物理年龄定曲线，而是以真实健康分 h₀ 反推"等效健康年龄"，再沿退化曲线外推到失效阈值；同时用维修台账真实条数延寿。这一升级让"修得好 → 健康分高 → 等效年轻 → 寿命更长"的完整逻辑打通。

100→40健康区间（跌破40判需维修）
h₀当前健康分 = health_score_final
realRepair维修台账真实「已验收」条数（替代 ⌊age/8⌋）
t_eq反推的"等效健康年龄"（维修后更年轻）

4.1 参数（系统默认值，可调）

参数值含义
tc8退化转折年（前段线性/后段二次分界）
hc60转折点健康值
tend12理论寿命（年）
hMin40失效/维修阈值（跌破即判需修）
repairExtend2.5每条真实维修记录延寿年限

4.2 升级核心：等效年龄反推 + 维修真实计数

U2 维修真实计数 realRepair = COUNT(repair_records WHERE 已验收/审核通过 AND end_date 非空) Tend' = tend + realRepair × repairExtend // 修得越多，理论寿命越长 U1 健康分反推等效年龄 k₁ = (100 − hc) / tc // 前段线性斜率 若 h₀ ≥ hc：t_eq = (100 − h₀) / k₁ // 前段线性反解 否则： t_eq = tc + √(1 − h₀/hc)·(Tend' − tc) // 后段二次反解 失效点（按 t_eq 所在段决定外推方式）： 若 t_eq ≤ tc：t_end = (100 − hMin) / k₁ // 前段线性外推 否则： t_end = tc + √(1 − hMin/hc)·(Tend' − tc) // 后段二次外推 剩余寿命 residual = t_end − t_eq，clamp 0 ≤ residual ≤ 12
为什么之前会误判？（升级前 1527 栋"紧急维修"的根因）
  • 旧模型用 age=今年−建成年 直接在曲线上定位，一旦 age ≥ T'end 就"超龄"；
  • 维修回弹依赖 theoreticalH>0，而老房 age ≥ T'end 时 theoreticalH=0，门槛被挡住 → 健康分再高也救不回；
  • 维修次数用 ⌊age/8⌋ 估算，与维修台账无关。

升级后改用健康分反推等效年龄 t_eq 替代 age：老而健康者变为"等效年轻"，不再归零；维修次数取真实台账，维修越多延寿越准。

真实示例A 老房 09-420527KF00018（2009建·升级后修正）

计算过程（健康分反推，不再归零）

5.4 分数分隔是否合理（给评委的分隔依据论证）

健康等级 5 档（90 / 75 / 60 / 40）

  • 90 为"优良"门槛：部件近乎全新或高维护，退化仍处于 CDCI 稳定区，风险冗余足；
  • 75 为"良好"门槛：大体对应部件进入线性退化中段（Δ t ∈ 0.2L~0.5L）而仍未到加速区，可正常使用但要定期维护；
  • 60 为"一般"门槛：与 BDRL 转折点健康值 Hc=60 同源——健康分低于 60，意味着部件已越过线性退化进入加速劣化，老化开始显现，必须关注；
  • 40 为"预警/危险"界：与寿命失效阈值 H_min=40 完全同源——跌破 40 即视为"已无有效剩余寿命"，必须维修，是两套分级共用的硬底线。

结论：健康 5 档的两处关键节点（60、40）刻意与寿命模型的 Hc、H_min 共用同一数值，保证"健康分级"与"寿命预警"在健康分上无缝衔接、互为印证，避免两套体系打架。

寿命预警 4 档（>7 / 4–7 / 0–4 / ≤0）

  • >7 年·正常：等效年龄偏低、安全冗余充足，对应健康"优良/良好"；
  • 4–7 年·需关注：进入设计寿命中后期，对应健康"一般"，开始纳入立计划观察；
  • 0–4 年·建议维修：临近退役窗口，对应健康"预警"，安排当年维修更换——与设备大修周期、年度养护计划对齐；
