烤房健康分与剩余寿命 融合算法详解

从信息化采集的基础数据出发，先算出烤房健康分（三维融合模型），再把健康分作为输入推算剩余寿命（BDRL 双段退化模型），最后把两个结果回流到勘察、养护和投建决策。以下每一行公式、每一个示例数值，均对应系统真实计算逻辑与真实数据库取值，可用本机复算核对。
输入 · 建设年度 / 部件状态 / 管护制度 / 人工评价 / 维修台账 健康分 · 部件 80% + 管护 10% + 人工 10% 寿命预测 · BDRL 双段退化 + 维修延寿 + 维修回弹

第 1 步 信息化数据从哪来（输入层）

系统为每栋烤房建立"一房一档"，健康分与寿命所需的全部数据来自以下四类信息化记录：

① 烤房档案
kf_basedata：建成年度(finish_date)、乡镇/村、使用状态
② 部件台账
加热器/散热器/自控/主体四张部件表：状态、评价、上次修复年份
③ 管护·人工
manage_mode（集中/分户）、manual_eval（好/中/差）
④ 维修台账
repair_records：已验收/审核通过 + 完工日期(end_date)
⑤ 退化折算
由年份差折算部件已使用年限 Δt，进入退化函数
⑥ 输出
健康分 0-100 + 剩余寿命(年) + 风险部位排序
🔑 每条数据的用途
  • 建成年度 → 计算房龄与部件已使用年限 Δt；
  • 部件状态 + 上次修复年份 → 状态分 S_status 与退化分 S_degrade 的输入；
  • 管护制度 / 人工评价 → 三维融合中的第 2、3 维，体现"管不管"与"现场复核"；
  • 维修台账 → 四级分类后重置部件退化年龄（修一修、退化重新起算）。

第 2 步 健康分三维融合算法

主公式
H健康分 = 0.80 × C部件 + 0.10 × M管护 + 0.10 × A人工 // 满分 100

部件 80 分、管护 10 分、人工 10 分 —— 与《三个模型建模初步建议》的"主要部件80 + 现行管护制度10 + 人工评价10"结构完全一致，但部件内部权重采用本项目实际运行的 4 组加权框架（见下）。

2.1 部件健康分 C部件（权重 80% 的承载主体）

C部件 由四组部件按权重加权（加热设备 JR + 散热器 SR + 自控设备 ZK + 烤房主体 ZT），每组部件内部再由"状态 + 退化 + 评价"三维构成：

C部件 = 0.30·JR + 0.26·SR + 0.26·ZK + 0.18·ZT // 权重来自 AHP 层次分析（加热最重要、散热与自控次之、主体最低） 某部件 Ci = 0.40·S状态 + 0.30·S退化 + 0.30·S评价
部件组权重对应部件表子项（状态列）
JR 加热设备0.30kf_heater燃烧机 burner_status
SR 散热器0.26kf_radiator管道 / 燃烧室 / 灰门 / 烟囱
ZK 自控设备0.26kf_controller冷风门/电机/排湿窗/循环风机/助燃风机/控制柜/水壶/探头（8项）
ZT 烤房主体0.18kf_oven_body墙体屋顶 / 挂烟梁 / 大门（3项）

2.2 三个子分是怎么定的

子分取值
S状态正常=100 · 异常=50 · 损坏=0
S评价较好=80 · 一般=60 · 较差=50 · 差=30
S退化见右：CDCI 三段式退化函数

2.3 退化分 S退化 —— CDCI 三段式

Δt = 今年 − max(部件修复年份, 维修台账最新完工年份) // 未修过按默认 5 年起算 稳定区 Δt ≤ 0.2L → 100 线性区 0.2L < Δt ≤ 0.7L → 100 − k₁(Δt − 0.2L), k₁ = 100/(0.5L) 加速区 Δt > 0.7L → 30·e^(−k₂(Δt − 0.7L)), k₂ = 2/L

L 为该部件的设计寿命（JR=10、SR=12、ZK=10、ZT=20 年，可在界面调）。年龄越接近寿命终点，退化越快——贴合烤房设备真实老化规律。

2.4 管护分 M 与人工分 A（权重 10% + 10%）

维度档位 → 得分说明
管护制度 M集中管护=100 · 分户管护=80集中管护设备更统一、退化更慢
人工评价 A好=100 · 中=80 · 差=50技术员现场复核，吸收照片/表单覆盖不到的经验

管护与人工两维在界面中可直接下拉录入（管理管护制度 / 人工评价），未录入默认"集中管护 + 好"兜底（各给 10 分），保证每栋烤房都能算出分数。

2.5 维修台账联动（重置退化年龄）

读取该烤房在维修列表中"已验收 / 审核通过"且完工日期非空的维修记录，按维修类型与描述关键词把维修归到四个部件组（加热→JR、散热/热风→SR、自控/电路/探头→ZK、保温/屋顶/大门→ZT，无法归类的记入通用组 ALL），用其完工年份作为该部件的退化起始年：

退化起始年 = max( 部件表修复年份 , 维修台账最新完工年份 )

效果：修过关键部件的烤房，退化年龄重新从维修当天起算，健康分明显回弹——真实反映"修一修、更健康"的维护价值，也让维修投入直接体现在健康分上。

真实示例 老烤房 09-420527KF00018（2009年建，梅家河 肖家坪）

① 读取原始部件数据（表内真实值）
部件L 寿命状态评价修复年份Δt(2026)
JR 加热器10正常较好20224
SR 散热器(4项)12均正常较好20224
ZK 自控(8项)10均正常较好20224
ZT 主体20均正常较差墙体18/梁24/门098/2/17

维修台账中该房均为"已归档"（未验收、无完工日），触发不了重置，故退化年龄以部件修复年份为准。

② 逐部件算 Ci
  • JR：Δt=4 ∈ 线性区(2,7]，k₁=100/(0.5×10)=20 → S退化=100−20×(4−2)=60
    C_JR = 0.4·100 + 0.3·60 + 0.3·80 = 82.0
  • SR：Δt=4 ∈ 线性区(2.4,8.4]，k₁=100/(0.5×12)=16.67 → S_d=73.3
    C_SR = 40 + 22.0 + 24 = 86.0
  • ZK：同 JR → 82.0
  • ZT：三子项 S_d=(墙体8→60, 梁2→100, 门17→加速22.2)，平均=60.7
    C_ZT = 40 + 0.3·60.7 + 0.3·50 = 73.2
③ 汇总 → 健康分
C部件 = 0.30×82.0 + 0.26×86.0 + 0.26×82.0 + 0.18×73.2 = 81.5 M管护（集中管护）= 100 A人工（好）= 100 H = 0.80×81.5 + 0.10×100 + 0.10×100 = 65.2 + 10 + 10 = 85.2 分 → 良好

✅ 与系统中该烤房 health_score_final = 85.2 完全一致，可复算。

补充：建议书中给出的 10 个细分部件权重（加热器15/散热器15/自控仪20/循环风机5/屋顶10/挂烟梁5/电源5/发电机5/大门10/烟夹5，合计95需归一化）可作为后续把 4 组细化为 10 件的方向，当前项目先以 4 组简化加权落地，数据驱动再校准。

第 3 步 剩余寿命预测算法（BDRL 双段退化）

寿命预测不是孤立估算，而是以健康分为输入：用当前健康分 H₀ 唯一确定退化曲线起点，再按"前段线性、后段加速"的双段模型外推何时跌破维修阈值（H=40）。

100→40健康区间（跌破40判失效）
age已使用年限=今年−建成年
repairCount每8年视为1次大修延寿
H₀取健康分算法结果 health_score_final

4.1 参数（系统默认值）

参数值含义
tc8退化转折点（前段/后段分界年）
hc60转折点健康值
tend12理论寿命
hMin40维修阈值（跌破即判需修）
repairExtend2.5每次大修延寿年限

4.2 双段退化模型

repairCount = ⌊age / 8⌋ // 每8年=1次大修 Tend' = tend + repairCount × repairExtend 前段 age ≤ tc：H(t)=100 − k₁·t , k₁=(100−hc)/tc 后段 age > tc：H(t)=hc·[1−((t−tc)/(Tend'−tc))²]

解 H(t)=40 得到理论寿命终点 tend，剩余寿命 = tend − age。

4.3 维修回弹修正（健康分反哺寿命）

按年龄外推一个"理论健康分" theoreticalH；若实际健康分 H₀ > theoreticalH，说明这台烤房被维护得比模型预期好，按比例拉长剩余寿命：

if H₀ > theoreticalH and theoreticalH > 0: residual = residual × ( H₀ / theoreticalH ) clamp: 0 ≤ residual ≤ 12 // 极限寿命12年

真实示例A 新烤房 25-420527KF00023（2025建，杨林桥 白鹤洞）

计算（线性前段 + 回弹）
age = 2026 − 2025 = 1 ， H₀ = 95.2 repairCount = ⌊1/8⌋ = 0 → Tend' = 12 age(1) ≤ tc(8) → 前段：k₁ = (100−60)/8 = 5 tend = (100−40)/5 = 12 → 初值 11 年 theoreticalH = 100−5×1 = 95 回弹：95.2 > 95 → ×(95.2/95)=1.0021 → 约 11.0 clamp≤12 → 剩余寿命 11.0 年 → 正常

✅ 对应系统值 life_residual_final=11.0，预测退役年份 2037。

真实示例B 老烤房 09-420527KF00018（2009建）

计算（二次后段，暴露模型短板）
age = 17， H₀ = 85.2 repairCount = ⌊17/8⌋ = 2 → Tend' = 12+2×2.5 = 17 age(17) > tc(8) → 后段： ratio = √(1−40/60) = 0.5774 tend = 8 + 0.5774×(17−8) = 13.2 residual = 13.2 − 17 = −3.8 → 截断为 0 theoreticalH = 60×(1−((17−8)/17−8)²)= 0 回弹门槛 theH>0 不满足 → 不加回弹 剩余寿命 0 年 → 紧急维修

这台房健康分高达 85.2，却因"年龄已越过后段理论终点+回弹门槛限制"被判零寿命——这是本模型需要升级的点（见第 7 步）。

第 4 步 健康分 ↔ 寿命预测 如何融合贯通

正向链路：部件数据 + 管护/人工 → 三维健康分 H₀ → 作为 BDRL 退化曲线起点 → 输出剩余寿命、预警等级、预测退役年份。

H₀ → BDRL(H₀, age) → residual 年 → 预警等级 → 退役年份 residual ≤ 0 紧急维修 · ≤4 建议维修 · ≤7 需关注 · >7 正常

反馈链路：维修台账完工 → 重置退化年龄（健康分回弹）→ 寿命同样自动延长 → 考试成绩单双向联动、口径统一。

数据库多端同步：健康分写 health_score_final 并同步 current_health_score 与 ovens.health_score/health_level；寿命写 life_residual_final 并同步 current_life_residual 与 ovens.predicted_life_years。烤房列表、AI智能分析、BI大屏读到的是同一份数据。

第 5 步 寿命预测如何升级优化（给评委的改进路线）

⚠️ 当前模型发现的问题（真实数据暴露）

重算后 2442 栋中 1527 栋被判"紧急维修"（剩余寿命 0），其中大量 2009 年老房健康分高达76-85。根因：

  • ① 后排二次曲线在 t=Tend' 处理论H 归零，一旦 age≥Tend'，回弹修正的 theoreticalH>0 门槛被挡住，健康分再高也救不回 → 一刀切为 0；
  • ② 维修次数用"⌊age/8⌋"粗暴估计，未关联维修台账真实记录；
  • ③ 设计寿命、转折点 hc/tc 均为固定经验值，未用历史数据拟合。
✅ 升级方案（科学、可解释、不失简洁）
  • U1 健康分直接驱动寿命：用实际 H₀ 反解退化曲线，而不是"年龄定曲线"。当 H₀>theoreticalH 时，用健康分反推上一时刻应处的"等效年龄"，再外推寿命——老而健康者不再被误判归零。
  • U2 维修台账真实计数：用 repair_records 中已验收记录条数代替 ⌊age/8⌋，维修越多延寿越准，与健康分维修联动无缝对齐。
  • U3 参数数据驱动：待样本积累后，用历年健康分-寿命观测回归/最小二乘拟合 tc、hc、tend、k₂，替代固定经验值，模型随烤季数据持续变准。
  • U4 风险部位排序：把四部件健康分导出"风险排序"，寿命预警直接定位到"加热器先修还是主体先修"，指导上门检修优先级。
  • U5 融合成综合评价：健康分(现状) + 剩余寿命(趋势) + 维修紧迫度 → 形成"修缮优先级 P"，供烟农培育辅导排期、年度养护计划直接使用。

参考建议书："烤房寿命分级 ≤0紧急维修 / ≤4建议维修 / ≤7需关注 / >7正常"在本项目已落地为 final 预警等级；上述 U1-U3 即为下一版升级点，可在寿命预测界面一键切换后重算验证。
