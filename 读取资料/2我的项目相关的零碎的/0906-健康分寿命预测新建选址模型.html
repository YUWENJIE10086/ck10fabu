模型一 烤房健康分 POST /barn/health-algo/final-apply

接口 code：HealthAlgoController.calculateFinalHealthWithRisk；落库字段：kf_basedata.health_score_final → ovens.health_score / health_level

本模型用到的方法 多指标加权综合评价 AHP专家主观赋权 三阶段退化曲线 CDCI 维修事件驱动的状态重置 短板风险排序 阈值分级评定

一句话 "烤房健康=部件自身结实程度（80%）＋管护是否到位（10%）＋技术员人工评价（10%）。" 部件分不是拍的，而是用 12 个关键部位各自的状态、剩余寿命占比、维修情况逐项打分后再归一。

1. 总公式（0906 最终口径）

H = P_norm × 0.80 + M × 0.10 + E × 0.10 // 0 ≤ H ≤ 100 P_norm ：部件归一化健康分（0–100） M ：管护制度分 集中管护=100 · 分户管护=80 E ：人工评价分 好=100 · 中=80 · 差=50

3. 单个部位得分

score_i = 100 × ( 0.50 × S_status + 0.35 × R_remain + 0.15 × C_eval ) S_status 状态系数： 正常 → 1.0 · 异常/老化 → 0.7 · 损坏/损毁 → 0.3 · 缺失 → 0 · 缺失状态 → 0.7 R_remain 剩余寿命比 = 剩余年限 / 指导寿命（修复年 → 已用年限回零回春） C_eval 归一化评价：优良/好=1.0 · 差=0.5 · 缺省=0.8 贡献 contribution_i = weight_i × score_i / 100 部件归一化 P_norm = Σ contribution_i / Σ weight_i × 100

4. 健康等级（5 档）

等级阈值运维含义
优良≥ 90状态好，按周期巡检即可
良好75 ≤ H < 90基本健康，关注少数部件
一般60 ≤ H < 75存在老化部件，纳入计划性维修
预警40 ≤ H < 60多部件明显劣化，尽快检修
危险H < 40接近/处于失效，立即处置

5. 维修记录联动（repair-sync）

寿命续期 ext
新采购→+2.0 · 改造升级→+1.5 · 防护加固→+1.0 · 其他→+0.8 若动作含"更换/替换" 再 +0.5 extSum ≤ 6.0 封顶
健康加分 boost
新采购→+5 · 改造升级→+4 · 防护/维护→+2 · 其他→+3 含"更换/替换" 再 +2 boostSum ≤ 12 · 新健康 ≤ 99

6. 示例（一栋 2010 年烤房）

按 12 部位状态、修复年、评价归一化逐项求出 contribution， 再归一并叠加管护/人工： 部件归一化 P_norm ≈ 74 H = 0.80×74 + 0.10×100(集中管护) + 0.10×100(评价好) = 79.2 分 → 良好 风险排序：按 gap×重要度 取前3，写入 risk_part1/2/3

模型二 剩余寿命预测 POST /barn/health-algo/life-final-apply

接口 code：HealthAlgoController.calculateFinalLifeWithParts；落库字段：kf_basedata.life_residual_final → ovens.predicted_life_years

本模型用到的方法 木桶短板约束 约束加权平均 健康分数校准（回归型修正） 状态系数折减 维修重置（失效回生） 阈值分级预警

一句话 "整栋烤房还能用几年，由最‘短’的部件说了算（占60%），再参考整体平均状态（40%），最后用健康分校正。"

1. 总公式

life = clamp( ( 0.60 × 短板寿命 + 0.40 × 部位加权平均寿命 ) × F_h , 0 , 15 ) F_h = clamp( 0.75 + H/400 , 0.60 , 1.10 ) // 健康分校准 H=100→F_h=1.00 · H=60→0.90 · H=40→0.85 预计退役年 = 当前年 + ceil(life)

2. 部件剩余年限 + 维修重置 + 数据兜底

remaining_i = max( 0 , (指导寿命 − 已用年限) × 状态系数 ) 已用年限 = 当前年 − max(建成年, 该部件最近维修完工年) // 修过→回春 状态系数：正常1.0 · 异常0.7 · 损坏0.3 · 缺失0 缺数据兜底：指导寿命按 5 年，已用按 0，标记"待补采"

3. 预警等级（4 档）

等级阈值(life)运维含义
紧急维修≤ 0已到/超期，立即处置
建议维修0 < life ≤ 4纳入当年维修计划
需关注4 < life ≤ 7跟踪监测
正常life > 7健康，按周期巡检

4. 示例

9个实装部件 + 屋顶/墙体短板： 短板寿命 = 屋顶/墙体最低剩余 = 0（维修超期，状态异常截断） 部位加权平均寿命 ≈ 4.1 年 健康分 H=78 → F_h = 0.75 + 78/400 = 0.945 life = (0.60×0 + 0.40×4.1) × 0.945 ≈ 1.6 年 → 建议维修 预计退役年 = 2026 + 2 = 2028 · 急需部件TOP3：屋顶/墙体、散热管、自控探头

模型三 新建选址 / 千亩村补建 GET /site-new-build/village-load

接口 code：SiteNewBuildController.villageLoad / recommend；落库字段：qianmu_village_decision_stats（development_index / need_score）

本模型用到的方法 加权综合指数法（50/30/20） 有效烤能状态折算 承载力评估（供需压力比） 需求反推测算 分档打分 情景分析（扩张韧性模拟）

方法定位 现状用的是主观定权的加权综合指数骨架。若要上"专门的选址算法"，可在其上叠加 区位熵LQ 灰色预测GM(1,1) 最大覆盖选址 整数规划MILP TOPSIS 等方法（见文末"方法库与可叠加创新"）。

一句话 "先把每个村现有烤房折算成'真正能用的烤能'，跟烟叶需求比一比，缺得越多、越不匹配，新建优先级越高。"

1. 总公式

V = 0.50 × Hc + 0.30 × Lc + 0.20 × Dc 需求分 N = 100 − V // 分数越低越要新建 Hc 有效烤能指数 · Lc 承载匹配指数 · Dc 发展因子指数

2. 单栋有效烤能与村级折算

E_i = 健康分/100 × capacityKg × 状态系数 (capacityKg 默认 5000 kg/座) 状态系数：在用=1.0 · 闲置=0.4 · 损毁/待修=0.1 · 其他=0 村级加权有效烤能 Q = 0.70×在用A + 0.20×闲置B + 0.10×待修C 理论需求 D = 收购量kg(烟叶事实表, 担×50) | 否则 面积×capacityKg/20 有效烤能指数 Hc = min( 100 , Q/D×100 )

3. 承载压力与承载匹配指数

P = D / max(Q, 1) Lc = P≤0.85→100 · P≤1.00→85 · P≤1.20→70 · P≤1.50→50 · 否则→30

4. 发展因子 Dc（5 项各 0.20）

因子计算口径
规模增长 growth面积≥1000→85 · ≥800→70 · 否则50
管护缴费 maintenance在用占比×100（40~100 区间）
政策争取 policy有候选点→85 · 无→70
服务能力 service有在用烤房→75 · 无→40
扩张韧性 resilience模拟面积+10%/5%/2%仍可承载→100/80/60 · 否则40

5. 推荐新建栋数 & 推演

负载率 loadBefore = 收购kg / (在用栋数 × capacityKg) 推荐栋数 needBarns = ceil( loadBefore − 1.0 ) // 补到不超负荷 新增推演：Q' = Q + 新增栋数×capacityKg Hc'、Lc' 重算 → V' = 0.50Hc' + 0.30Lc' + 0.20Dc 改善值 ΔV = V' − V（越大说明建得越值）

补充 新建点位评价：AHP + 熵权法 + TOPSIS POST /site-new-build/evaluate

接口 code：SiteNewBuildController.evaluate / SiteSelectionController.evaluate（两套同口径，8 项指标）

本模型用到的方法 层次分析法AHP（Saaty） 熵权法（信息熵客观定权） 组合赋权 多准则决策MCDA · TOPSIS

一句话 "在‘该不该建’（千亩村指数）之外，还要回答‘建在哪好’——用 AHP 请专家定重要性，用熵权让数据自己说话，再用 TOPSIS 挑离理想点最近的候选地。"

8 项指标 & 主观权重： 地形地势 0.15 · 水文条件 0.12 · 电力保障 0.18 · 交通条件 0.10 烟田匹配 0.20 · 环境安全 0.10 · 集群效益 0.08 · 成本经济 0.07 步骤： ① 每个候选点 8 指标量化打分 ② AHP 两两比较 → 主观权重；熵权法 → 客观权重 ③ 组合赋权 W = α·W主观 + (1−α)·W客观 (α 默认 0.6) ④ TOPSIS：找正/负理想解 → 贴进度 Cᵢ → 排序

这是两套并行的选址入口：SiteSelection（全量点位选址）与 SiteNewBuild（新增点位 + 千亩村供需缺口），前者只用 AHP+熵权+TOPSIS 评点位，后者叠加千亩村指数定"建哪里、建几栋"。

收口 三模型如何串成一条链

数据库台账(kf_basedata / 部件表 / repair_records / 烟叶事实表) │ ▼ 逐部件健康分 健康分 H = 部件80%·管护10%·人工10% → ovens.health_score / health_level（五级） │ 以 H 与部件剩余年限为输入 ▼ 寿命预测 寿命 life=(0.6短板+0.4均值)×clamp(0.75+H/400) → ovens.predicted_life_years（四级预警） │ 以健康分×容量×状态 = 有效烤能为输入 ▼ 村级新建选址 V=50%Hc+30%Lc+20%Dc · N=100−V · needBarns → 千亩村新建优先级 ▼ 点位评价 AHP+熵权+TOPSIS 8指标 → 最终落址排序

2. 创新名方法库（按主题归类）

① 定权重 · 综合评价 层次分析法 AHP · 熵权法 · 组合赋权 已用 · 数据包络 DEA（评估"投入座数→烘烤效益"） · TOPSIS/VIKOR/ELECTRE（多准则排序）
② 寿命 · 可靠性 威布尔分布（Weibull 寿命拟合） · 生存分析/Kaplan-Meier · FMEA（失效模式与影响）已用其"风险优先级"思想 · 灰色 GM(1,1) 寿命外推
③ 选址 · 承载（重点补新建这块） 区位熵 LQ（判"够不够"） · 最大覆盖选址 / 集覆盖模型（判"建几栋覆盖几家"） · 重心法/引力模型（判"建在哪省运输"） · 设施可达性 · 整数规划 MILP（预算×栋数×容量求最优补建）当前开发指数尚未用，可叠加
④ 需求预测 灰色预测 GM(1,1) · 多元回归 · 时间序列（LSTM/ARIMA移植）——用历年烟叶面积/收购量预测未来规模，反推"该建几栋"
⑤ 智能增强（第二轮会话方案，可并行） LSTM 时间序列预测未来健康分 + 随机森林做预警分级与归因，与机制模型"决策融合"： RUL = 0.35 × LSTM预测寿命 + 0.65 × 机制模型寿命 随机森林 ← (RUL阈值, 健康分, 发热gap, 维修统计, 村级指数) → 预警等级 + 概率 + 归因
