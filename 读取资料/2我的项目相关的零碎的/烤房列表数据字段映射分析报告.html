烤房列表数据字段映射分析报告

前端展示字段 ↔ 后端API返回字段 ↔ 数据库表字段

📊 数据源概述
主要数据源

烤房列表数据来源于两个核心数据库表：

  • kf_basedata 表 - 存储烤房基础信息（地理位置、建设方式、项目类型等）
  • ovens 表 - 存储烤房运行状态（使用状态、健康评分、温度湿度等）
数据查询方式

通过 LEFT JOIN 将两个表关联，确保基础信息和运行状态数据同时返回

🔌 API端点信息
主要API接口

GET /barn/project/list - 烤房列表查询接口（分页）

GET /barn/project/assign-list - 烤房分配专用列表接口

🗄️ 数据库表结构

👨‍🌾 bakers 表（烤烟员信息）

id (主键)
name (姓名)
通过 bakers.id = ovens.baker_id JOIN 关联

✅ 核心结论

烤房列表数据通过 LEFT JOIN 方式从 kf_basedata 和 ovens 两个表获取：

  • kf_basedata 表 提供烤房的基础信息（编码、地理位置、建设方式、项目类型、健康评分等）
  • ovens 表 提供烤房的运行状态（使用状态、温度湿度、烤烟员、使用次数等）
  • bakers 表 通过 JOIN 提供烤烟员姓名信息
  • 前端显示字段通过后端 API 返回的映射字段实现展示
⚠️ 注意事项

1. 数据同步：kf_basedata 和 ovens 表通过 project_id 字段关联，确保数据一致性
2. 默认值处理：当 ovens 表中某字段为空时，使用 kf_basedata 表的对应字段或默认值
3. 状态字段：use_status（使用状态）和 facility_status（设施现状）来自 kf_basedata 表
4. 运行状态：status（运行状态）来自 ovens 表，用于区分当前是否在烤
5. 健康评分：优先使用 kf_basedata.current_health_score，若为空则使用 ovens.health_score
