烤房寿命预测 · 从“整栋反推”升级为“逐部件短板融合”

针对项目现状设计的一版寿命预测升级方案：健康分已定稿（三维 80/10/10），全部指导寿命已核定，因此寿命预测不再满足于“拿整栋健康分反推一条曲线”，而是把每个部件的指导寿命、修复年度、状态逐一算进来，用“短板约束”决定整栋剩余寿命，同时保留整栋健康分做校验与主观判断留口。本方案只写设计，供 0905 定稿。

现状梳理 寿命预测界面现在是怎么跑的

当前“寿命预测算法”页面默认使用最终版 BDRL（0901 升级版），核心是用整栋健康分 health_score_final 反推“等效健康年龄”，再沿退化曲线外推到失效阈值，并用维修台账真实条数延寿：

当前 剩余寿命 RUL（逐栋） 输入：当前年；建成年；健康分 h₀ = kf_basedata.health_score_final（缺失默认70） 参数：tc=8年；hc=60；tend=12年；hMin=40；repairExtend=2.5年/条 维修真实条数 realRepair = COUNT(已验收/审核通过 且 end_date非空) T_end' = tend + realRepair × repairExtend 等效年龄 t_eq： h₀ ≥ hc → t_eq = (100 − h₀) / k₁ , k₁ = (100−hc)/tc 否则 → t_eq = tc + √(1 − h₀/hc)·(T_end' − tc) 失效点 t_end： t_eq ≤ tc → t_end = (100 − hMin)/k₁ 否则 → t_end = tc + √(1 − hMin/hc)·(T_end' − tc) RUL = clamp(t_end − t_eq , 0 , 12)
它的进步（已解决）
  • 不再用“物理年龄”一刀切 → 老而健康房不再被判 0 年（升级前 1527 栋紧急维修 → 升级后 70 栋）；
  • 维修次数用真实台账计数，修得越多理论寿命越长。
它还没解决的问题（本次升级抓手）
  • 整栋只给一个数，看不见“哪个部件先到期” —— 无法回答维修决策问得最多的“下一步该修哪儿”；
  • 用整栋健康分反推，会掩盖短寿命部件：一栋自控仪仅剩 2 年余、其余良好、健康分 85 的烤房，会被算出 9 年寿命，与“自控仪最易损坏”的实际规律冲突；
  • 指导寿命已核定但没进寿命模型（加热外置10/内置12、散热15、自控6、屋顶未盖6/盖15、挂烟梁木10/钢15、烟夹6 等尚未逐件参与）；
  • 数据不完整部件没有兜底口径，与健康分侧的“5年兜底”不对齐。

一句话：现有寿命是“整栋健康分给一个答案”，升级后的目标是“让每个部件告诉我们这栋烤房还差几年，再由最短的短板决定整栋”。

升级依托 两张现成的“王牌”

① 健康分已定稿（逐部件、可归一、有兜底）
  • 三重输入：部件状态、修复年度、人工评价；
  • 归一化公式 P_norm = Σ(Wᵢ·Lᵢ·Sᵢ)/Σ有效Wᵢ ×100，数据不全部件按 5 年兜底仍参与；
  • 直接可复用到寿命侧：部件健不健康 ↔ 部件还能用几年。
② 指导寿命已核定（主要部件全清单）
  • 加热外置 10 年 / 内置 12 年；散热器 15 年；自控仪 6 年；
  • 易损件：出风百叶窗 5 年、烟夹 6 年、大门 10 年；
  • 主体：屋顶未加盖 6 年 / 加盖 15 年；挂烟梁柱木质 10 年 / 钢材 15 年；电源电线、发电机 10 年。

有了这两张王牌，就能把寿命预测从“单值宏观曲线”升级为“逐部件微观算盘 + 整栋短板约束”。

设计思想 四层模型：部件 → 部位 → 整栋 → 决策

L1 部件层
每个部件按指导寿命Tᵢ + 修复年度算剩余年限 rᵢ（数据不全兜底）
L2 部位层
加热/散热/自控/主体 四部位各自聚合
L3 整栋层
短板约束 ⊗ 整栋健康分反推，合成 RUL
L4 决策层
风险部位排序、预警、修缮优先级、退役年份
为什么纵向拆到部件、横向合成短板是对的（贴合实际 + 融合主观）
  • 贴合实际：烤房是否可用高度依赖部件；一栋烤房的寿命短板往往就是最先老化的部件（实测样例健康分71分，风险排序 自控仪＞烟夹烟梁＞加热散热，与实际损坏规律吻合）；
  • 融合主观：人工评价、状态判断本就存于数据，作为“部件可信度”与“整栋修正”的主观留口；服务队现场复核可整级覆盖最终预警；
  • 可解释：每个数字都能落到“某个部件用了几年、还剩几年”，维修人员能直接看懂、能讲给评委。

核心 升级主公式（BDRL-U6 逐部件短板融合）

L1 部件剩余年限 rᵢ
已用年限 Aᵢ = 今年 − max(部件修复年, 维修台账该部件组最新完工年) 缺修复记录 → 按烤房建成年 两者皆缺（数据不全）→ 兜底口径(见第六节) 剩余 rᵢ = max(0, Tᵢ − Aᵢ) × Sᵢ + repairBonusᵢ Tᵢ 按类型/材质查指导寿命表 Sᵢ 状态修正(正常1/异常.7/损坏.3/缺失0) repairBonusᵢ = 该部件真实维修条数×1.5年
L2 部位层 / 短板项
部位剩余 Rⱼ = Σ(wⱼᵢ·rᵢ) / Σwⱼᵢ (部位内第j组部件加权) 整栋结构短板 R_b = 0.6 × min(参与部件 rᵢ) // 最弱部件主导 + 0.4 × Σⱼ(wⱼ·Rⱼ) // 部位整体水平 wⱼ = 加热.30 散热.26 自控.26 主体.18
L3 整栋合成 + 校验
整栋健康分反推 RUL_w（沿用现有U1） h₀ → t_eq → t_end − t_eq 短板融合 RUL = α·RUL_w + (1−α)·R_b α∈[0,1] 推荐0.5（可调：信任整栋 vs 信任结构） 主观修正 RUL_final = RUL × K_man K_man 由人工评价/服务队复核： 好1.05 / 中1.00 / 差0.90（可整级覆盖） clamp 0 ≤ RUL_final ≤ L_max
三处“主观判断”留口（本方案刻意做得“既客观又可调”）
留口主观判断点默认谁来改
α 融合权重更信“整栋健康分”还是“部件短板”0.5县局/专家按片区实际调
K_man 修正系数人工评价/服务队对整栋寿命的复核印象好1.05/中1.0/差0.9技术员、服务队现场判定
指导寿命 Tᵢ 局部覆盖某村设备老化普遍偏快，可下调 Tᵢ按表合作社/专家按村校准

上下限按“保守档”缺省：缺材质按较短年限、缺类型按主流行情，宁可保守一点，避免高估寿命；若当地设备普遍耐用好，由专家按村上调。

补充条款 数据不完整时寿命侧怎么兜底（与健康分同口径）

情形寿命侧兜底标记
部件缺状态、修复年、种类任一按数据不完整：Tᵢ兜底5年、Sᵢ=1.0、不叠加维修激励（保守）待补采
维修台账缺“已验收/完工日”不计入 realRepair；也不算部件 reset（与健康分一致）待归档
某部位完全无部件记录该部位权重不参与分母归一，不强行补分归一
整栋部件数据全部不全退回“纯整栋健康分反推 RUL_w”，至少给一条曲线结论退化为RUL_w
健康分 h₀ 缺失用默认 70 分反推，并在界面标“健康分缺失-默认”默认
修复年度缺、只有建成年已用年限按建成年算（真实可得的年数），不强行置0按建成

原则：缺数据不剔除、也绝不虚增寿命——能算的按真实年数算，算不了的按 5 年保守兜底并标记待补采，等补录后立即按真实指导寿命重算。这样表格里不会出现一堆“寿命真空”的烤房，也不会出现“缺数据反被高估”的误导。

联动 维修台账怎么“反着”喂寿命

部件级重置（比整栋更精细）

Aᵢ = 今年 − max(部件修复年, 该部件组最近完工年) → 修过自控，自控的已用年限就从维修完成年重算 → 该部件剩余 rᵢ 明显回弹 （不再只是在理论寿命上加2.5年）

效果：把维修“计入寿命”从宏观加时，落到“具体哪个部件被新了一次”，更接近真实。

整栋真实计件延寿（沿用）+ 维修轨迹

realRepair = 已验收且完工的维修条数 维修轨迹 = 按部件组分别计：JR/SR/ZK/ZT/ALL → 哪个组维修多，说明该组是老化的短板， 寿命预警自动指向它（呼应风险部位排序）

维修记录沿部件组归类，与健康分侧 computeRepairMap 共用一套归类逻辑，口径统一。

主观融入 “客观数据 + 主观判断”如何各就各位

客观量化（自动，可溯源）
  • 建设年度、部件修复年度、指导寿命；
  • 维修台账真实条数、完工日期；
  • 健康分（逐部件归一化结果）。
半主观（有据，系数化）
  • 部件状态（正常/异常/损坏）→ 修正 Sᵢ；
  • 人工评价（好/中/差）→ 整栋 K_man；
  • 业务重要度（自控1.25/加热1.15/散热1.15）→ 风险排序加权。
主观裁量（专家留口）
  • α 融合权重按片区调；
  • 指导寿命 Tᵢ 按村校准；
  • 服务队现场复核可整级覆盖预警等级。

这套分层刻意保留“人的判断”入口，既不牺牲可复现性，又贴合基层“技术员看一眼更准”的真实习惯，且每次人都能改、系统能存、可被后一次的自动计算尊重。

示例 老房 09-420527KF00018（2009建 · 健康分85.2）——短板怎么拖低整栋

逐部件剩余年限（修复年 2022，当前 2026）
部件指导寿命 Tᵢ修复年→Aᵢ剩余 rᵢ(T−A)状态S维修条数rᵢ×S
加热器122022→48正常1.008.0
散热器152022→411正常1.0011.0
自控仪62022→42正常1.002.0
主体（门/梁/屋顶）6~20门09/梁24~3正常1.003.0
min(参与部件 rᵢ) = 2.0（自控仪，短寿命件） 部位整体 = (8+11+2+3)/4 ≈ 6.0 R_b = 0.6×2.0 + 0.4×6.0 = 3.6 年 整栋健康分反推 RUL_w = 9.0（沿用现有U1，85.2→9.0） 融合 α=0.5：RUL = 0.5×9.0 + 0.5×3.6 = 6.3 年 K_man = 1.0（人工“好”）→ RUL_final = 6.3 年 预警等级：需关注（4–7年），退役约 2032 风险部位排序第一：自控仪

对比：只信整栋健康分 → 9.0 年“正常”，但现场逻辑是“自控仪仅剩 2 年余，这栋烤房真正要先盯的是自控”。融合后 RUL=6.3 年“需关注”，并把风险部位指向自控仪，与实测样例“风险部位自控仪第一”吻合。α 敏感性：0.3→5.2 / 0.5→6.3 / 0.7→7.5 / 0.9→8.7，便于按片区定策略。

落地 如何从“整栋 BDRL”平滑升级（不推翻现有）

保留 + 增补
  • 保留：U1 健康分反推等效年龄、U2 维修真实计数、现有预警分级与 ovens.predicted_life_years 同步链路；
  • 增补：部件层计算、短板约束 R_b、α 融合、K_man 主观修正、风险部位排序；
  • 新增字段：life_component（各部件剩余年限片段）、life_short_part（短板部件名）、life_conf（可信标记：完整/兜底/退化）。
数据流（延续现状即可）
逐部件(指导寿命+修复年+状态) → 部件剩余 rᵢ → R_b 短板 健康分 h₀ → RUL_w ──→ RUL=α·RUL_w+(1−α)·R_b └→ ×K_man → RUL_final → 预警等级 → 退役年份 → ovens.predicted_life_years

前端仍按剩余寿命显示色块与预警，整数清晰；新增“部件剩余寿命明细”可在详情弹窗展示，方便维修人员下钻。

评估 升级前后对比 + 给评委的一句话

升级前
  • 整栋健康分给“一个年限”；
  • 短寿命部件被整体平均掩盖；
  • 回答“还剩几年”，不回答“先修哪”；
  • 数据不全无兜底口径。
升级后
  • 逐部件给剩余年限 + 整栋短板；
  • 自控等短寿件直接暴露；
  • 回答“还剩几年 + 先修哪个部件”；
  • 数据不全 5 年兜底并归一，不虚增。
给评委一句话

“寿命预测从‘整栋给一个数’升级为‘让每个部件的指导寿命和修复记录告诉我们还差几年’，用最短短板决定整栋、用人工判断做修正——修得好、短板就短，寿命自然就长。”
