# 智烤管家｜8分钟决赛视频与系统截图植入初稿
生成时间：10092010

## 一、总原则：视频少而强，截图真而准

结合现有111主版、9.30演讲稿、3S共享烤房旧版、三智融合0909版、读取资料/2我的项目相关的零碎的，以及上一年度获奖作品发布方式，建议决赛现场采用“1段开场视频 + 1段系统实操短视频 + 5—7张真实系统/模型证据图”的组合。

不要做成“系统功能说明会”。评委真正需要看到的是：
1. 这个问题确实存在；
2. 你们确实做出了系统和模型；
3. 系统真的能完成关键动作；
4. 最后确实产生了可核验结果。

因此，主线仍然保持现在的“1234”：
**1个数据库 → 2大模型 → 3大功能 → 4支队伍。**
视频和截图只作为证据，不抢叙事。

## 三、开场30秒AI视频：保留，但建议只做“背景+情绪+三难”

你已经确定用原30秒AI视频，这个方向是对的。它的任务只有一个：**让评委在30秒内理解为什么要做这个项目。**

建议30秒结构：
- 0–8秒：连续降雨、烟叶急需采烤，烟农找不到空闲烤房——“分不到”；
- 8–16秒：凌晨故障、温度上不去、电话找维修人员——“修不及”；
- 16–24秒：一边烤房紧缺、一边闲置/继续新建，管理人员难判断——“投不准”；
- 24–30秒：三个问题快速收束，最后定格“智烤管家”，画面出现**1 / 2 / 3 / 4**。

视频里不要提前把模型、AHP、TOPSIS、平台菜单讲完。视频只负责把矛盾拉满，后面PPT再负责回答。

如果原视频结尾没有“1234”，建议只改最后3—4秒，不用重做整段。

## 四、逐页“该加什么”初稿

### P1 封面
**不加系统截图。**
保留111的高级感，让AI视频最后一帧直接淡出到封面。
封面只强化“智烤管家”和黄色1234，不堆功能。

### P2 三难
建议仍以“大字三难”为主。
可在页面底部增加一条非常轻的证据线：
**“531份有效问卷 / 一线访谈 / 烘烤现场”**。
不要放完整问卷大屏，否则评委第一眼会去读小字。

可参考素材：
- `问卷情况展示.html` 只取其中一个统计结果做小型数据角标；
- 不建议直接整页截图。

### P3 三难背后的管理痛点
不放系统截图。
这页是“为什么过去解决不了”，最好保持逻辑图。
可以参考 `痛点-对策-0830-1.png` 的“问题→对策”思路，但不要原图整张贴入，应改造成111风格的无边框三段式逻辑。

### P4 1234总览
**完全不加截图、不加视频。**
这是整场最重要的“记忆页”。
只把：
**1个数据库 / 2大模型 / 3大功能 / 4支队伍**
做大、黄色数字、逐项出现。

### P5 1库｜数据库
这里第一次让评委看到“真系统”。

建议放：
- 一栋一档页面局部；
- 烤房列表/地图局部；
- 4大部位18个关键部件的小型拆解示意。

原则：只留一个主截图，其他做2个小局部放大，不要把后台整屏缩小到看不清。

这页要让评委形成一句话：
**“不是做了一张表，而是把每一座烤房做成了可更新的数字档案。”**

### P6 2模①｜健康评估模型
推荐素材：
- `1-烤房健康评估模型_健康分与剩余寿命_一页图.drawio (1).png`

但不要整图原封不动贴上去，因为信息太密。
建议裁成三步：
**数据输入 → 12部件计算 → 健康分/寿命/风险输出**。

右侧再放一个真实健康评分界面小截图，形成“模型不是纸上公式，而是已经进系统”。

讲述重点只留一句：
**“模型回答两件事：现在健不健康，下一步先修哪里。”**

### P7 2模②｜发展导引/新建决策
这一页最应该上真实截图。

**首选素材：`新建决策web.png`。**

理由：
- 有地图；
- 有真实烤房点；
- 有红色候选点；
- 有发展指数；
- 有村级排序；
- 一眼就像“真正能用的决策系统”。

建议版式：
左侧约40%讲三步：有效烤能→承载匹配→发展指数；
右侧约60%直接放新建决策Web截图。

截图要裁掉无关浏览器边缘，重点放大：
**红色候选点 + 千亩村发展指数 + 候选点列表。**

这一页是整个项目“科技感”和“决策含金量”最强的一页之一。

### P8 双模决策
不再增加新截图。
用P6、P7的模型结果缩略图汇聚成一句：
**先调剂 → 再修复 → 仍有结构性缺口才新建。**

这样形成“不是为了建而建”的决策价值。

### P9 3智总览
推荐参考：
- `1-智用智投智管_协同关系图_含两个模型(2).drawio.png`

同样不要整张复制，内容太多。
建议只抽三列：
**智用 / 智投 / 智管**
底部用一条线串：
**业务发生 → 数据回库 → 模型再算 → 决策再优化。**

### P10 智用｜这里放第二段、也是最后一段系统视频
这页建议放**20—25秒真实小程序录屏**，而不是静态截图。

直接从 `小程序视频演示脚本.docx` 中只截两段：
1. **预约调剂**：选日期→系统查询空闲烤房→健康/距离排序→选中；
2. **一键报修**：现场定位→选故障→提交→维修进度时间线。

不要演示：
- 登录；
- 隐私协议；
- 个人中心；
- 完整评价；
- 全部筛选按钮。

这些适合验收，不适合决赛。

建议视频节奏：
- 0–8秒：预约；
- 8–15秒：推荐结果；
- 15–21秒：一键报修；
- 21–25秒：维修进度闭环。

A/B角只在视频前后各说一句，中间让系统自己说话。

### P11 智投
继续使用真实系统，但不要再播视频。

推荐：
- `新建决策web.png` 作为新建侧；
- 健康分/维修清单作为修复侧。

用“左右双证据”：
左：**该修谁**；
右：**该建哪里**。

避免再次解释AHP公式。这里讲“模型最后给管理者什么”。

### P12 智管
推荐放真实的：
- 维修工单列表；
- 工单时间线；
- 巡检/验收/评价回写；
- 管护资金看板。

`ai助手web.png` 可以保留，但只占右下角15%左右，作为加分项：
比如只露出：
**“哪些烤房健康分低于60？”**
**“剩余寿命不足5年的有哪些？”**

不要把AI助手单独讲成第五个创新点，否则会冲淡1234主线。

### P13 4队｜这一页不要再放系统截图，放“人”
这是当前材料最值得补的一类：**实地照片。**

优先级：
1. 紧急抢修现场照片；
2. 合作社配件仓/备件照片；
3. 日常养护或巡检照片；
4. 四支队伍合照或服务现场。

最好是“一张主图+三张窄图”，不要四个证件照式小框。

这一页评委需要看到：
**“不是只有平台，线下真的有人接住。”**

如果目前照片不足，宁可先留位置，不要用AI生成假现场图代替证据。

### P14 成效｜大数字仍然是主角
继续保持现在的大数字舞台表达。
不要把FineBI整屏直接贴满。

最多补两个证据缩略图：
- 一张维修工单/调剂记录；
- 一张BI统计或资金台账。

推荐把 `FineBI烤房智管全项目大屏设计方案.html` 里的主驾驶舱思路用于后续真实BI截屏，但注意报告数据口径必须统一后再上屏。

### P15 总结
不放任何系统截图。
回到：
**1库 → 2模 → 3智 → 4队**
和项目口号。

可以用AI开场视频最后的烤房/烟田大景作为非常淡的背景，实现首尾呼应。

## 七、从优秀获奖发布里应该学什么

优秀作品共同特点不是“视频多”，而是**场景视频负责抓人，真实系统负责证明，数字结果负责定胜负**。

可以直接套到智烤管家：
- 开头先让评委感受“急”——烟叶要烤、设备坏了、钱该投哪；
- 之后立刻用1234给出非常简单的解决框架；
- 中段不要连续讲理论，而是每讲一个模型就立刻告诉评委“它最后帮谁做了什么决定”；
- 至少出现一次真实系统操作，让评委确信不是PPT项目；
- 至少出现一次真实现场照片，让评委确信不是纯软件项目；
- 成效页只讲最硬的数字，不解释页面功能；
- 最后20秒回到行业推广价值，而不是继续展示菜单。
